# HHMS Database Schema

---

## 1. Purpose

This document defines the physical database structure for the Homoeopathic Hospital Management System (HHMS). It translates the approved business entities into a normalized relational database schema suitable for implementation.

The schema specifies database tables, columns, primary keys, foreign keys, constraints, relationships, and indexing requirements. It serves as the authoritative reference for backend implementation and database migration.

This document follows the approved entity model defined in DATABASE_ENTITIES.md. No new business entities shall be introduced within this document.

---

## 2. Database Design Principles

The HHMS database shall follow these principles:

- Normalize data to minimize redundancy.
- Use integer surrogate primary keys for all tables.
- Preserve referential integrity through foreign keys.
- Store historical records without physical deletion.
- Keep optional module tables independent of mandatory modules wherever possible.
- Support offline-first operation.
- Optimize for low-resource hardware.
- Maintain compatibility with future ABDM/FHIR data mapping.
- Avoid database-specific features that reduce portability.
- Follow consistent naming conventions across all database objects.

---

## 3. Primary Key Strategy

HHMS shall use integer surrogate primary keys for all database tables.

Primary keys shall:

- Be unique.
- Be immutable.
- Be generated by the database.
- Never be reused.

Business identifiers (such as Patient Number or Invoice Number) are separate from primary keys and may be displayed to users without exposing internal database identifiers.

Foreign key relationships shall reference the internal primary key.
