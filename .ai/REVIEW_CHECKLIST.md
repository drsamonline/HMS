# REVIEW CHECKLIST

## Task Verification Checklist

Use this checklist before marking any task as complete.

---

## Code Quality

- [ ] No duplicate code (DRY principle followed)
- [ ] No hardcoded values (configurations externalized)
- [ ] Clear, descriptive naming for all identifiers
- [ ] Functions are small and focused (single responsibility)
- [ ] Business logic separated from infrastructure
- [ ] Error handling is appropriate
- [ ] No commented-out code left in files

---

## File Modifications

- [ ] Only files relevant to the task were modified
- [ ] No unrelated refactoring or reformatting
- [ ] New files are in correct directories
- [ ] File names are clear and descriptive
- [ ] No temporary or backup files committed

---

## Documentation

- [ ] README.md updated (if applicable)
- [ ] CHANGELOG.md updated with changes
- [ ] Inline comments added where needed
- [ ] API documentation updated (if applicable)
- [ ] .ai/PROJECT_STATE.md updated
- [ ] .ai/PROGRESS.md updated
- [ ] .ai/SESSION_LOG.md updated
- [ ] TODO.md checkboxes updated

---

## Constitution Compliance

- [ ] Follows PROJECT_CONSTITUTION.md rules
- [ ] No scope creep (only requested features)
- [ ] Architecture unchanged (unless explicitly required)
- [ ] Offline-first design maintained
- [ ] Modularity preserved

---

## Testing

- [ ] Unit tests written (for new functionality)
- [ ] Existing tests still pass
- [ ] Edge cases considered
- [ ] Error conditions tested

---

## Git Hygiene

- [ ] Commit message is clear and descriptive
- [ ] Only related changes in single commit
- [ ] No sensitive data committed
- [ ] Branch is up to date (if applicable)

---

## Final Verification

- [ ] All requirements met
- [ ] No obvious bugs or issues
- [ ] Code compiles/builds successfully
- [ ] Manual testing performed (if applicable)
- [ ] Ready for review/merge
